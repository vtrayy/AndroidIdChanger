# 兼容性与验证矩阵

本文区分“可构建/可安装”“普通应用查看”和“Xposed 运行时已实测”。没有实测的组合不写成正式保证。

## Android 系统范围

| Android / API | legacy APK | modern APK | 说明 |
| --- | --- | --- | --- |
| Android 4.2～7.1 / 17～25 | 支持构建与安装 | 不支持安装 | legacy 使用纯 Java 与 Xposed API 53，无 native 库 |
| Android 8.0～16 / 26～36 | 支持构建与安装 | 支持构建与安装 | 实际 Hook 能力取决于框架和目标方法 |
| Android 17 / 37 | 支持构建与安装 | 支持构建与安装 | `compileSdk/targetSdk 37`；传统 Build 字段修改严重受限 |

“支持构建与安装”不代表所有敏感标识符都能读取。Android 10 起，普通应用通常无法取得 IMEI、MEID、序列号、IMSI 和 ICCID；应用会显示权限或脱敏状态。

## Xposed 入口

| 框架类型 | 建议变体 | 状态 |
| --- | --- | --- |
| 原版 Xposed | legacy | 入口格式与 API 53 兼容；具体 Android 版本按原框架支持范围 |
| LSPosed 原版 API 兼容模式 | legacy | 接口级兼容；包含建议作用域与传统共享配置声明，仍需按 LSPosed 与 Android 版本实际验证 |
| libxposed API 102 兼容框架 | modern | 现代入口、scope、module.prop 与 RemotePreferences 已实现 |
| EdXposed | legacy | 官方项目声明 Android 8.0～11 与原版 API 兼容；其他版本不作保证 |
| 太极、VirtualXposed 及其他容器/变种 | legacy 优先 | 实验性；系统服务、作用域和配置读取能力可能缺失 |

LSPosed 公共仓库目前列出的稳定支持范围为 Android 8.1～14；超出该矩阵的 fork 或新实现必须按其自身文档判断。框架能加载模块也不等于每个 Hook 点都有效。

参考：[原版 Xposed API 使用说明](https://github.com/rovo89/XposedBridge/wiki/Using-the-Xposed-Framework-API)、[LSPosed](https://github.com/LSPosed/LSPosed)、[EdXposed](https://github.com/ElderDrivers/EdXposed)、[libxposed API](https://github.com/libxposed/api)。

## 替换能力边界

| 类别 | legacy | modern |
| --- | --- | --- |
| Android ID | Hook `Settings.Secure` 公共/兼容方法 | Hook `Settings.Secure.getString` |
| IMEI/MEID/电话/SIM | 按运行时存在的方法安装 Hook | Hook API 26+ 公共方法 |
| Wi-Fi/蓝牙地址 | Hook 公共 getter | Hook 公共 getter |
| `Build.getSerial()` / `getRadioVersion()` | 方法存在时 Hook | 两者均 Hook |
| `Build.MODEL` 等静态字段 | 尽力修改，失败静默降级 | 不修改 |
| native、系统属性、硬件证明 | 不支持 | 不支持 |

Android 17 对静态 final 字段的反射/JNI 修改施加更严格限制，因此不能承诺 `Build.*` 字段直读会被替换。详见 [Android 17 行为变更](https://developer.android.com/about/versions/17/behavior-changes-17)。
